# 資料及儲存契約

## RC4 既有資料

集保快照按統計日保存，含代號、分母、級距股數與戶數、觀測時點、來源、校驗及缺值理由。官源及月交易日曆由本機服務管理，同日官源修訂另存；策略與手動快照依賴瀏覽器儲存。日 K 依代號快取並附擷取時間。實際欄位見 RC4 的 `serve_local.py`、`weekly_evidence.py` 與前端 `storage-adapter.js`。

## 目標資料契約

原始、標準化、衍生分層。以交易或統計日期、資料類型、來源、代號與修訂識別資料；日期為 YYYY-MM-DD，時點帶時區。分開保存事件日、可用時間、擷取時間與版本，未知可用時間為 null。保留原始 SHA-256、授權、涵蓋、缺值原因和品質檢查。逐時點查詢選擇截止時已可用的版本。股數與戶數為整數，資料單位須明示。

共享資料採程式與資料 repo 分離。全域 catalog 導向年度資料庫，再依月與個股讀片。一般使用者網路優先且預設不永久保存市場資料。順序為工作階段 RAM、共享庫、合法來源或使用者匯入。此決策優先於 Skill 的預設磁碟快取。RAM 需限容量及 TTL、合併相同請求、限並行、支援取消與限流退避；跨年月依日期分段。HTTP、瀏覽器、SQLite 及本機檔案均須遵守相同保存界線。作業暫存於完成或失敗後清除，舊資料與使用者明確保存的內容獨立保護。普通用戶預設唯讀。

完整包 manifest 的最低契約見 [發布決策](DECISIONS.md)。相容性有明確資料 schema 範圍，保護資料與程式槽位分開。

索引依 dataset、market、instrument_id 與 code 描述分片。保存起迄日、觀測日、統計日、取得與可證公布時間、revision、data_version、來源 URL、涵蓋及缺漏理由、列數、單位、交易範圍、格式、壓縮、大小、SHA-256、授權及轉發許可、資產位置與驗證狀態。空索引明示尚無資料。管理者先驗證、去重與上傳不可變分片，遠端核對後才更新索引；修訂另存。

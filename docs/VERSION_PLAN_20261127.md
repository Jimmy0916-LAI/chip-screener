### 2.3 共用架構與歷史檔案

建議沿用現有資料服務及看盤前端。EXE 管理連線、資料寫入、回測和匯出；HTML 從使用者選取的快照讀取相同欄位與畫圖元件。股東門檻、交易日對齊、指標計算只維護一套規則。若兩端語言不同，可由核心算好結果再供 HTML 顯示。允許修改 main 啟動主檔、拆分服務和整合入口；每次調整以正常啟動、體積、速度、回歸結果說明取捨。

| 資料 | 建議保存單位與用途 | 更新／復原 |
| --- | --- | --- |
| 股票母體、交易日曆、集保週資料、日行情 | EXE 管理一個本機資料目錄；可沿用現有檔案，資料多時用 SQLite 索引市場、股票、日期、涵蓋區間與修訂版 | 首次手動取得必要資料。以來源日期補缺，保留上次有效版本與研究引用的版本。 |

**發放歷史資料。** 安裝包只附小型來源索引或其位置。索引記載市場、股票代碼、月份、資料種類、日期、大小、雜湊、版本、下載位置及允許用途。優先採混合方式。允許轉發的資料可以從專案 GitHub 提供；只允許個人下載時，程式以使用者資格連原來源，或讀使用者匯入檔。私庫發布資產的權限與資料來源的轉發資格須各自確認。來源消失或撤回時，已驗的本機資料仍能依其使用條件查詢。

**容量與完整性。** 2 GB 是可調的本機歷史預算提示。先用 2330、2404、6261 的實檔量出每股每月的下載量、解壓後含索引占用、暖機量與更新尖峰空間，再依股票數及月份估算。資料頁列「已存／缺期／來源未提供／停牌／驗證失敗」，下載前預估增加量。一般用戶可只存自選期間；專案持有人可指定本機目錄、提高預算、保留全部已取得的歷史並備份。超額時先讓使用者選擴充、縮短下載範圍或清理可重建資料。用「有資料的日期數／應有資料的交易日數」呈現完整率，零成交、休市與來源缺檔分開記錄。

## 3. 0.6.3 開發規格

### 3.1 P0 先修集保更新

1. **重現。** 用原 ZIP 分別測第一次雙擊、按「更新市場資料」、已有快取時更新。記錄 Windows 版本、實際入口、時間、程式版本、來源、錯誤與日誌。檢查網路／HTTP 回應、CSV 欄名和編碼、統計日、股票母體版本及覆蓋率、週次新舊與雜湊、權限、寫入、更新事件及前端重算。候選根因由重現或日誌支持。
2. **核對官方。** 由集保官方股權分散入口確認實際檔案和統計日，搭配正式交易日曆。保存取得時間、統計日、來源證據、雜湊及可確認的可用時點。政府資料目錄的更新頻率欄寫每月，集保官方說明指出統計基準是每週最後營業日，程式用資料實際日期及發布證據判斷新舊。不可把下載時間當成歷史首次發布時間。 [集保官方說明](https://www.tdcc.com.tw/portal/zh/smWeb/qryStock) · [政府資料目錄](https://data.gov.tw/dataset/11452)
3. **正確寫入與重算。** 驗欄位、級距、每檔股數與分母、日期、重複及母體覆蓋。查到覆蓋不足時比對來源口徑和名單版本，保留原因。通過驗證才原子切換有效快取，更新首頁、週篩選、個股圖和資料狀態。一次更新共用同一個工作，再按按鈕可看到進度；同一期重抓保持冪等。既有 A/B 用同一週與同一母體。保留上次驗證成功資料與可追溯的修正版。
4. **狀態讓使用者看得懂。** 分開顯示「尚未下載」「已是最新」「新一期尚未發布」「更新成功」「部分成功」「更新失敗，已保留上次資料」。首頁至少顯示集保統計日、行情交易日、上次成功更新、重試入口。離線、回舊資料、空檔、格式變更或資料寫入中斷時，保留舊資料並給出原因。
5. **第一關通過條件。** 從空資料狀態連網首次更新成功，再以較舊且已驗證週資料為基線，透過**候選 EXE 的正常按鈕取得可核對的真實新一期**。畫面在原視窗刷新且重新啟動仍讀得到；另測同一期重抓和失敗保留。Windows CI、固定資料測試和 Windows 11 真實連網各留證。若官方當下沒有新一期，可用較舊快取驗證目前的官方檔。缺少真實更新證據時，P0 狀態標為待驗或阻塞，保留診斷和續跑入口。

### 3.2 P1 整合與本機雙入口

- **發行資料夾。** Windows x64 ZIP 解壓後第一層只有 `股票雷達.exe`、`股票雷達輕量版.html` 和一個執行資源資料夾。使用者雙擊、免裝 Python。EXE 乾淨安裝無預載市場資料也能斷網開啟、切換既有七頁和進設定。需要的前端、執行環境、字型和圖表資源隨包提供。搬到含中文與空格路徑可再次開啟。
- **HTML。** 由共用畫面輸出可雙擊啟動的輕量前端。第一次開啟無資料時，顯示「選擇資料檔」，並告知如何在 EXE 更新後「匯出輕量資料」。匯出的快照至少含格式版本、資料日期／期間、來源、涵蓋與可用欄位；匯入驗版本和格式，失敗維持前一次可用畫面。更新時由使用者再選新檔，網頁與 EXE 無須背景同步。優先採瀏覽器 File API，避免 `file://` 直接讀鄰近資料庫的限制。 [MDN 本機檔案](https://developer.mozilla.org/en-US/docs/Web/API/File_API/Using_files_from_web_applications) · [MDN 本機來源限制](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS/Errors/CORSRequestNotHttp)
- **兩端一致。** 圖表、資料欄位和篩選共用同一份規則或同一來源預算好的結果。相同快照和條件下，股票名單、排序、篩選命中、集保日期數字和 OHLC 應一致。使用者換機可透過明確匯出／匯入實現，不需登入自建服務。量測 ZIP 與解壓容量、冷啟動時間、HTML 及初次匯入的大小，歷史資料按需分股載入。
- **架構與既有操作。** 開發 AI 可重構桌面入口、合併共用模組或更換執行容器。基準方案為先將已可運行的入口與資料服務整合，再依兩端一致性、維護成本、啟動與體積的實測決定是否有必要更換。留下架構決策、依賴、資料格式、相容遷移及復原步驟。0.6.2 的既有功能依實際入口逐項驗證，故障行為以新版可運行結果交代。
- **疊加日 K。** 在「200 張、400 張……」旁顯示可獨立操作的「疊加日 K」。日 K 畫開、高、低、收，與集保週點用同一交易日期軸。價格與持股各有縱軸。週點依資料原始統計日對齊，短交易週、停牌、缺週與缺行情顯示實際狀態。驗證多級距並存、切股、縮放和舊有自選。市場資料首次更新取全市場名單、篩選必需的近期集保及最新日行情，長日 K 開個股時再補。
- **本機資料清除。** 設定顯示下載位置、日期、類型與占用空間。清除功能先列出範圍和大小，讓使用者確認。保留自選股、策略、手動補登和受保護歷史。確定可重建的快取可清除；日後歷史容量先以 2 GB 作提示和可調預算，依需求增加、只留自選股或縮短區間。

**時間對齊範例。** 選漢唐 2404，同時勾 200、400 張級距，再勾「疊加日 K」。游標指到某個統計日，提示顯示該日 OHLC、各級距的值與單位；其餘交易日可看 OHLC，持股欄顯示最近一期及原始日期，或明示無當日觀測。不得把週持股複製成每日新觀測。若統計日個股停牌，保留週點並標記無 K 棒。圖上統計日用於比較，回測另按資料可用時點決定何時能產生訊號。

**交付順序。** 先完成真實集保更新及失敗保留，再整合雙入口、疊圖和版本更新；若 P0 尚待外部環境驗證，其餘可獨立開發，整版報告保留 P0 待驗。首次離線開啟首頁應看得出下一步，連網按「更新市場資料」後，在同一視窗看到新統計日和可點選的股票；再次斷網，仍能打開剛才那筆結果。

| 1. 建立當日成交分布 | 優先用經核對的交易所／供應商分價，或將真實逐筆按價加總。將單邊成交股數正規化為各價占當日成交的比例 q。其次可用分鐘 OHLCV，把每根量依記錄清楚的規則分配至區間價格後加總；最後沿用日 K 估算。同一天資料重疊時選一個已驗來源。 |
| 2. 更新舊成本 | 延用既有模型並記錄公式版本。可驗的基準公式為每價格格 C新 = (1 − w) × C舊 + w × q，其中 C 是估算持倉比重，w 是當日舊籌碼被換手的估計比例。分母採來源可追溯且當日可用的股數；若採「單邊成交股數／股數」線性換手，須將 w 限於 0～1 並記錄截限、股數變動、缺分母與適用範圍。若既有版本採不同衰減，先以固定案例比對並保存舊版參數。 |

**短 K 的用途。** 1 分 K 比日 K 多了日內價格區間，有機會縮小成交分配誤差。每根 K 仍只有開高低收與總量，同一根可對應不同分價。即使取得真實分價，當天賣出的人原本在哪個價位買進仍是模型假設。因此畫面應寫「成交分價輸入・持倉成本估算」或「1 分 K 區間估算」等具體名稱。先對照同日真實分價，量測各價量占比絕對誤差總和與峰價誤差，再決定分鐘備援是否值得儲存；不可用更短時間框架直接宣稱已還原市場成本。

- 每策略保存名稱、版本、參數、所需資料和可用時點。比較畫面支援同一市場母體、基準期間及執行假設的獨立策略並排；個別策略的不同設定要清楚可查。缺資料列明原因，不能跨缺週或讀取未來資料。不同策略可重用同一可靠回測引擎。
- 每次回測保存資料版本、日曆、訊號日時、執行規則、交易成本、滑價、未成交處理與結果。輸出報酬、最大回撤、筆數、交易明細及必要覆蓋。先用固定案例手算、相同設定重跑、測有無未來資料的產出一致性。正式績效僅限資料和假設已驗的範圍，回測限本機研究與模擬。

#### 0.8.0 條件、交易規則與比較畫面

**操作流程。** 使用者從現有大股東策略複製一份，新增條件、選「全部／任一」、設定參數，預覽每檔股票為何命中或缺資料，儲存為有版本的策略。將兩份或更多策略加入比較，選市場、起迄日、初始資金、部位規則、費用及滑價。開始後顯示進度；完成可點某筆交易，回看當時的指標、可用資料日與成交假設。

| 條件 | 建議第一版可獨立核對的定義 |
| --- | --- |
| 大股東連續增持 | 沿用已驗的 200／400 張等級距、持股股數與持股占比欄位；連續週次、股數差及百分點變化依策略參數。週次中斷時顯示缺期；只在資料已發布後提供回測訊號。 |
| 日線 MACD 黃金交叉 | 建議預設快／慢／訊號為 12／26／9。DIF 採快慢 EMA 差，訊號線為 DIF 的 EMA。前一交易日 DIF ≤ 訊號線，當日 DIF > 訊號線即命中；記錄 EMA 初始化、暖機、價格調整與缺行情規則。 |
| 突破壓力、跌破支撐 | 可重現的首版建議採「前 N 日高低」，預設 N = 20。今日收盤嚴格高於先前 N 個有效交易日最高價為向上突破，嚴格低於最低價為向下跌破；當日排除在參考窗外。介面使用「突破前 N 日高點／跌破前 N 日低點」，便於區分使用者未來可能自訂的支撐壓力算法。 |

建議同版交付上述技術條件；承接原企劃的最低門檻為「至少一項經獨立驗證的新策略或條件組」加上可用的多策略回測。報告逐項寫明交付狀態。在出現缺資料的條件上保留「未知」與原因。全部符合時，任一失敗則不命中，全部通過才命中；任一符合時，一項通過即命中，全部失敗才不命中。其餘狀態為未知，畫面獨立計數。

**回測實作。** 以某交易日當時的母體、已可得資料、策略版本，產生與畫面相同的訊號。初版可用「收盤後產生訊號、下一可交易日開盤模擬成交」為預設，週資料依實際可用時間判定；歷史發布時間無憑證時採明示的保守假設，或排除該段。回測啟動前具體指定買入、退出、同日多訊號的排序與資金分配、交易單位、費用與滑價。停牌、缺開盤價、資金不足、成交受限時依策略保存的規則延後或取消，列明原因。復權訊號與實際成交價、公司行動、股利處理口徑各自保存，避免重複計入。

**結果與交接。** 每套策略並排顯示期間報酬、最大回撤、已完成交易筆數、資料覆蓋及未成交數。交易明細可查訊號時點、執行時點、股數、成交價、費用、現金和部位；保存策略參數、資料快照識別、引擎版本、排序規則和期末持倉估值。相同輸入下重跑，應可重建當日資產與最終數字。
